## Domain 1: Information Architecture & Navigation

### D1-1 — CRITICAL: Ten flat top-level items exceed cognitive ceiling

**File:** `src/components/layout/AppLayout.tsx:72-113`

The nav bar renders all 10 items at identical visual weight with no grouping. Miller's Law places the comfortable limit at 7 +/- 2 items. The 10 items fall into distinct categories that are not signaled:

- Data Ingestion: Upload, Review, Calendar
- Analysis: Dashboard, Trends, Analytics
- Output: Documents, Reports
- Configuration: My Company, Rules

**Recommendation:** Collapse to 5 nav items with grouping. See Product Restructure Plan.

### D1-2 — HIGH: "Review" and "Rules" are ambiguous names

**File:** `src/components/layout/AppLayout.tsx:81-83, 109-112`

"Review" means "validate AI extraction quality" but reads as "review a document." "Rules" is a developer abstraction — the page configures benchmark document generation.

**Recommendation:** "Review" -> "KPI Validation", "Rules" -> "Generation Rules" (or absorb into Settings).

### D1-3 — HIGH: Route/URL incoherence — /settings/benchmark-rules in top nav as "Rules"

**File:** `src/App.tsx:72-73`

The URL `/settings/benchmark-rules` implies a settings section exists, but there is no settings section in the nav. The URL path contradicts its nav placement.

**Recommendation:** Either route to `/benchmark-rules` or create an actual `/settings` parent route.

### D1-4 — HIGH: ApprovalChainsPage is completely unreachable

**File:** `src/App.tsx:73`

Route `/settings/approval-chains` exists but has zero NavLinks pointing to it — desktop or mobile. The page is invisible.

**Recommendation:** Add nav link or surface under Settings.

### D1-5 — HIGH: "Documents" vs "Reports" distinction invisible from labels

**File:** `src/components/layout/AppLayout.tsx:85-88, 101-104`

Both look like "places where output files live." Documents = auto-generated benchmark docs. Reports = custom user-built. Icons (`FileText` vs `FileBarChart`) are too similar.

**Recommendation:** Merge into single "Reports" page with tabs, or rename: "Benchmark Docs" + "Report Builder."

### D1-6 — MEDIUM: Nav order does not match strategist workflow

**File:** `src/components/layout/AppLayout.tsx:73-112`

Current order front-loads Dashboard but buries "My Company" at position 9. A new user lands on peer comparison before entering their own data.

**Recommendation:** Reorder to match setup-then-analyze workflow.

### D1-7 — MEDIUM: Horizontal nav will not scale beyond 10 items

**File:** `src/components/layout/AppLayout.tsx:72`

No overflow behavior — no "More" dropdown, no secondary nav. Adding feature 11 breaks layout silently. Already overflows at 1280px (most common corporate laptop resolution).

**Recommendation:** Migrate to left sidebar or collapse to 5 items with overflow menu.

### D1-8 — MEDIUM: Mobile drawer has no scrim, no grouping

**File:** `src/components/layout/AppLayout.tsx:154-210`

10 stacked items with no section headers. No overlay/scrim behind the drawer. User can interact with content below it.

**Recommendation:** Replace with slide-in side sheet with dark scrim overlay and grouped sections.

### D1-9 — MEDIUM: "My Company" placement and naming creates ambiguity

**File:** `src/App.tsx:75-76`, `src/components/layout/AppLayout.tsx:105-108`

Position 9 of 10 does not signal that it is foundational. The sub-route `/my-company/benchmark` (MyBenchmarkPage) is also not in the nav — a second orphaned page.

**Recommendation:** Move to Settings or surface benchmark results on Dashboard.

### D1-10 — LOW: Settings gear icon on "Rules" creates false affordance

**File:** `src/components/layout/AppLayout.tsx:109`

The `Settings` (gear) icon universally signals application settings. Using it for a domain-specific feature trains the user to expect a full settings page.

**Recommendation:** Change icon to `SlidersHorizontal` or `ListChecks`.

## Domain 2: Interaction Design & Workflows

### D2-1 — CRITICAL: `confirm()` dialogs for destructive deletes (3 places)

**Files:**
- `src/pages/ReportBuilderPage.tsx:141`
- `src/pages/CalendarPage.tsx:250`
- `src/pages/BenchmarkRulesPage.tsx:280`

Native `window.confirm()` blocks JS thread, cannot be styled, breaks Playwright tests, and is jarring in a polished dark UI.

**Recommendation:** Replace with shared `<ConfirmDeleteDialog>` using `<Dialog>` from shadcn/ui.

### D2-2 — CRITICAL: Upload wizard — no recovery after mid-pipeline failure

**File:** `src/pages/UploadPage.tsx:224-230`

If extraction succeeds but normalization fails, the user is stuck. If they navigate away, `reportId` is lost — no persistence, no resume.

**Recommendation:** Persist `reportId` in URL or sessionStorage. Show "Retry" + "Start Over" on error states.

### D2-3 — CRITICAL: ReportViewerPage draft state has wrong CTA

**File:** `src/pages/ReportViewerPage.tsx:118-123`

Draft state says "Click 'Regenerate' to generate" but the Regenerate button is in the header toolbar, not in the empty state. User must scroll up to find it.

**Recommendation:** Add primary "Generate Report" button inside the draft empty state.

### D2-4 — HIGH: Upload wizard requires manual button click at each step

**File:** `src/pages/UploadPage.tsx:259-302`

After upload: click "Extract KPIs." After extraction: click "Normalize to CHF." After normalizing: click "Generate Benchmark." Three additional clicks for a pipeline with no branching decisions.

**Recommendation:** Auto-chain pipeline. Add optional "Run Full Pipeline" button.

### D2-5 — HIGH: ReviewPage — approve-only, no reject/edit/bulk

**File:** `src/pages/ReviewPage.tsx:82-107`

No way to correct a wrong value, flag for re-extraction, or reject. No bulk-approve. 50 items = 50 individual clicks.

**Recommendation:** Add inline edit, "Reject/Mark Error" action, and "Approve All" with confirmation.

### D2-6 — HIGH: ReportBuilderPage — no navigate after create, View gated to 'ready'

**File:** `src/pages/ReportBuilderPage.tsx:117-125, 199-204`

View button only appears when `status === 'ready'`. Draft reports have no View or Edit action. After creation, dialog closes with no prompt to generate.

**Recommendation:** Navigate to report viewer after create. Make View available for all non-generating statuses.

### D2-7 — HIGH: MyCompanyPage KPI editor DATA-LOSS BUG

**File:** `src/pages/MyCompanyPage.tsx:178, 187-209`

`values` state initialized empty (line 178), never pre-populated from `existingKpis`. If user edits one KPI and saves, only that field is in `values` — all other previously-saved values are silently dropped by the `.filter(([, val]) => val.trim() !== '')` on line 195.

**Recommendation:** Pre-populate `values` from `existingKpis` via `useEffect`.

### D2-8 — HIGH: TrendsPage year range — no validation

**File:** `src/pages/TrendsPage.tsx:141-159`

`startYear` and `endYear` selects are independent. Setting startYear=2024, endYear=2015 produces empty results with no explanation.

**Recommendation:** Clamp endYear >= startYear. Show inline error for inverted range.

### D2-9 — HIGH: CalendarPage "Check now" — single mutation disables all rows

**File:** `src/pages/CalendarPage.tsx:225-237`

`checkMutation` is page-level. `disabled={checkMutation.isPending}` disables ALL check buttons simultaneously. Spinner appears on every row's icon.

**Recommendation:** Track `checkingId` in state. Disable/spin only the active row.

### D2-10 — MEDIUM: AnalyticsPage scatter — no warning for same KPI on both axes

**File:** `src/pages/AnalyticsPage.tsx:85-109`

User can select same KPI for X and Y axes. Chart renders meaningless diagonal line.

**Recommendation:** Detect `xKpi === yKpi` and show inline warning.

### D2-11 — MEDIUM: BenchmarkRulesPage — no edit action, delete-and-recreate only

**File:** `src/pages/BenchmarkRulesPage.tsx:320-359`

Rule cards have no edit mode. Changing a single field requires deleting the rule and recreating it.

**Recommendation:** Add edit mode (inline expansion or dialog).

### D2-12 — MEDIUM: DocumentsPage — filtered-empty and genuinely-empty share same CTA

**File:** `src/pages/DocumentsPage.tsx:53-71, 174`

If user has documents but filters return zero, they see "Upload a Report" — wrong CTA. Should show "No documents match these filters — clear filters."

**Recommendation:** Differentiate unfiltered-empty vs filtered-empty states.

### D2-13 — MEDIUM: MyBenchmarkPage — re-run button gives no indication of replacement

**File:** `src/pages/MyBenchmarkPage.tsx:136-143`

"Run Benchmark" replaces current results with no warning.

**Recommendation:** Rename to "Re-run Benchmark" when results exist. Add note: "Will replace current results."

### D2-14 — MEDIUM: CalendarPage delete — no loading state, double-click fires duplicates

**File:** `src/pages/CalendarPage.tsx:248-261`

Delete button has no `disabled` state while pending. No spinner.

**Recommendation:** Track `deletingId`, disable per row, show spinner.

### D2-15 — MEDIUM: UploadPage — future fiscal year not validated in handler

**File:** `src/pages/UploadPage.tsx:238-255`

`max={CURRENT_YEAR}` is browser-only hint. No JS validation in submit handler.

**Recommendation:** Add explicit year range check in `handleUpload`.

### D2-16 — MEDIUM: ReportBuilderPage KPI list — 128px scroll, no select-all, no count

**File:** `src/pages/ReportBuilderPage.tsx:276-298`

`max-h-32` (128px) shows ~4 items. No search, no "Select All", no "X of N selected." BenchmarkRulesPage has "Select All" but ReportBuilder does not — inconsistency.

**Recommendation:** Add "Select All / Deselect All" toggle and "X of N selected" count.

### D2-17 — LOW: ReportViewerPage — regenerate doesn't auto-refresh content

**File:** `src/pages/ReportViewerPage.tsx:88-99`

After regenerate success, toast fires but page content doesn't refetch.

**Recommendation:** Invalidate report query on generate success.

### D2-18 — LOW: TrendsPage — chart shows only `trends[0]` when "All KPIs" selected

**File:** `src/pages/TrendsPage.tsx:73, 177`

Only first series rendered. User has no way to browse between KPIs.

**Recommendation:** Add KPI selector or "1 of N" navigation when multiple series exist.

### D2-19 — LOW: CalendarPage — "Auto-discover" button disappears once URL is filled

**File:** `src/pages/CalendarPage.tsx:526-553`

No way to re-run discovery or try again without manually clearing the field.

**Recommendation:** Show "Re-discover" button when URL already exists.

### D2-20 — LOW: ReviewPage empty state has no CTA to Upload

**File:** `src/pages/ReviewPage.tsx:46-58`

Empty state explains the condition but provides no action for a user with no uploads.

**Recommendation:** Add "Upload a report to begin extracting KPIs" link when queue is empty.

### D2-21 — LOW: BenchmarkRulesPage delete — no spinner while pending

**File:** `src/pages/BenchmarkRulesPage.tsx:349-357`

`disabled={deleteMutation.isPending}` present but no visual spinner — trash icon remains static.

**Recommendation:** Show `<Loader2 className="animate-spin" />` while pending.

## Domain 3: Visual Hierarchy & Data Presentation

### D3-1 — HIGH: H1 size inconsistent across pages

**Files:** `src/pages/DashboardPage.tsx:239` vs all other pages

Dashboard uses `text-[24px] font-semibold`. All other pages use `text-2xl font-bold sm:text-3xl`. On sm: breakpoints, Dashboard stays 24px while others jump to 30px. Weight differs: 600 vs 700.

**Recommendation:** Standardize to one scale. Extract `<PageTitle>` component.

### D3-2 — MEDIUM: Mixed select component patterns

**Files:** `src/pages/DashboardPage.tsx:248-262` (shadcn Select) vs `src/pages/TrendsPage.tsx:119-158` (native select)

Dashboard uses shadcn `<Select>`. Every other page uses native `<select>` which renders OS-default chrome that breaks dark theme.

**Recommendation:** Replace all native `<select>` with shadcn `<Select>`.

### D3-3 — CRITICAL: YAxis has no unit label or formatter

**File:** `src/pages/TrendsPage.tsx:184`

No `tickFormatter`, no `label` prop. Revenue in CHF billions renders as raw integers.

**Recommendation:** Add `tickFormatter` with `Intl.NumberFormat('en', { notation: 'compact' })` and unit label.

### D3-4 — MEDIUM: Hardcoded Tailwind color classes bypass signal tokens

**Files:** `src/pages/TrendsPage.tsx:249`, `src/pages/MyBenchmarkPage.tsx:154-156, 252-255, 308`

`text-green-500` and `text-red-500` used instead of `--color-signal-green` / `--color-signal-red`. In light mode these differ visually.

**Recommendation:** Replace with `text-[var(--color-signal-green)]` / `text-[var(--color-signal-red)]`.

### D3-5 — HIGH: Heatmap legend too small, color steps uneven

**File:** `src/pages/AnalyticsPage.tsx:375-383, 388-394`

6 color blocks with no tick labels. P39->P40 jumps from red to gray (gray reads as "neutral/missing"). No user can reverse-engineer percentile from color.

**Recommendation:** Add percentile tick labels. Consider continuous diverging scale.

### D3-6 — CRITICAL: Heatmap cell text contrast fails WCAG AA at P40-P60

**File:** `src/pages/AnalyticsPage.tsx:357-360`

At P40-P60: bg=#6b7280, text=var(--color-foreground)=#E8EAED. Contrast ~3.0:1 (needs 4.5:1).

**Recommendation:** Use `color: 'white'` at P40-P60 (white on #6b7280 = ~4.6:1).

### D3-7 — HIGH: Scatter plot has no on-chart company labels

**File:** `src/pages/AnalyticsPage.tsx:280-297`

Colored dots with company names only in external legend. Forces constant eye travel for 8-10 companies.

**Recommendation:** Add `<LabelList dataKey="company_name" position="top" fontSize={10} />` inside `<Scatter>`.

### D3-8 — HIGH: PercentileBar misaligned inside centered table cell

**File:** `src/pages/MyBenchmarkPage.tsx:307-317, 228-229`

`<th>` uses `text-center` but `PercentileBar` flex container has no `justify-center`. Bar renders left-aligned in centered cell.

**Recommendation:** Add `justify-center` to PercentileBar flex div, or change `<th>` to `text-left`.

### D3-9 — HIGH: Pivot table has no signal coloring

**File:** `src/pages/AnalyticsPage.tsx:186-193`

Every value in plain `text-foreground`. No percent-rank highlighting, no conditional formatting. Analytically inert for strategy audience.

**Recommendation:** Apply `getSignalClass` logic from DashboardPage.

### D3-10 — HIGH: Table header not sticky vertically

**File:** `src/pages/DashboardPage.tsx:307-335`

`<thead>` has no `sticky top-0`. Scrolling down loses column headers.

**Recommendation:** Add `<thead className="sticky top-0 z-20">` with `bg-card` on the `<tr>`.

### D3-11 — CRITICAL: bg-tertiary on card = 1.08:1 contrast — invisible

**File:** `src/index.css:111-112`

`--color-bg-tertiary: #1C1D20` on `--color-card: #141518`. Row hover states invisible. TabsList active tab imperceptible.

**Recommendation:** Increase tertiary to at least `#252629` (~1.4:1 perceived distinction).

### D3-12 — MEDIUM: ReportViewer H2 misclassified typographically

**File:** `src/pages/ReportViewerPage.tsx:141-142, 149`

Section headings ("Executive Summary") are `text-sm font-medium uppercase text-muted-foreground` — looks like label/caption, not H2.

**Recommendation:** Make section H2s `text-base font-semibold text-foreground`.

### D3-13 — MEDIUM: Calendar automation banner too heavy for persistent UI

**File:** `src/pages/CalendarPage.tsx:73-107`

~180px banner with 4 bullet points. Reference documentation, not UI. Daily users scroll past it every visit.

**Recommendation:** Collapse behind disclosure toggle. Show single-line summary by default.

### D3-14 — HIGH: MomentumBadge text-[10px] below WCAG minimum

**File:** `src/pages/TrendsPage.tsx:275-277, 297-304`

10px text fails WCAG 1.4.4 and is unreadable on 96dpi screens.

**Recommendation:** Raise to `text-xs` (12px) minimum.

### D3-15 — LOW: Missing tabular-nums verification (confirmed non-issue)

Verified in source — both start_value and end_value have `tabular-nums`. No action needed.

### D3-16 — MEDIUM: Muted foreground contrast borderline in interactive elements

**File:** `src/index.css:83`

`#9CA3AF` on `#141518` = ~4.55:1 — passes AA by razor-thin margin. Any opacity/weight reduction risks failure.

**Recommendation:** Raise dark `--color-muted-foreground` to `#A8B0BB` for 5.0:1+ comfort.

### D3-17 — HIGH: No column sort controls on any table

**Files:** `src/pages/DashboardPage.tsx:317-335`, `src/pages/TrendsPage.tsx:229-257`, `src/pages/AnalyticsPage.tsx:168-198`, `src/pages/MyBenchmarkPage.tsx:222-269`

Zero sort interactivity on any table. The most expected data table interaction for a benchmarking tool.

**Recommendation:** Add sort indicators and click handlers on `<th>` elements.

### D3-18 — MEDIUM: Peer Median line color clashes with grid in dark mode

**File:** `src/pages/TrendsPage.tsx:207-212`

`stroke="#6b7280"` hardcoded. Perceptually closer to grid lines than to data series.

**Recommendation:** Use `--color-accent` (#3B82F6) with dash pattern, or lighter neutral like `#A0AEC0`.

## Domain 4: Onboarding & Empty States

### D4-1 — CRITICAL: No first-run experience whatsoever

**File:** `src/components/layout/AppLayout.tsx` (all)

Zero onboarding: no welcome modal, no setup wizard, no progress banner, no checklist. New user sees 10 nav items and empty Dashboard. The hard prerequisite chain (Add company -> Upload reports -> Review -> Compare) is never communicated.

**Recommendation:** Add SetupProgress banner: "1 Add Company -> 2 Upload Report -> 3 Review KPIs -> 4 Start Benchmarking."

### D4-2 — CRITICAL: Analytics + Dashboard default to year with no data

**Files:** `src/pages/AnalyticsPage.tsx:30-31`, `src/pages/DashboardPage.tsx:177`

Both default to `new Date().getFullYear() - 1` = 2025. Actual data is in 2024. User sees empty page.

**Recommendation:** Auto-detect most recent year with data. Show "No data for 2025 -- showing 2024 instead" toast.

### D4-3 — HIGH: "Upload a Report" CTA skips company prerequisite

**Files:** `src/pages/DashboardPage.tsx:64-82`, `src/pages/DocumentsPage.tsx:53-71`

Empty states link to /upload but don't mention that peer companies are needed first. User can upload but comparison will be incomplete.

**Recommendation:** Check `companies.length === 0` and show "Start by adding your company" CTA first.

### D4-4 — HIGH: 10 nav items visible day 1 with no progressive disclosure

**File:** `src/components/layout/AppLayout.tsx:72-113`

5 of 10 items are dead ends until setup is complete (Review, Documents, Trends, Analytics, Reports).

**Recommendation:** Progressive unlock: grey out data-dependent items with tooltip "Add data to unlock."

### D4-5 — HIGH: Review empty state wrong for zero-upload state

**File:** `src/pages/ReviewPage.tsx:46-58, 143`

"All extracted KPI values have been reviewed" is factually incorrect for a user who has never uploaded anything.

**Recommendation:** Differentiate "empty because nothing uploaded" vs "empty because everything is clean."

### D4-6 — HIGH: Trends chart degenerate with 1 year of data

**File:** `src/pages/TrendsPage.tsx:35-36, 162-171`

One data point renders as a single dot cluster. No minimum-data guard. Year range defaults to 2021-2025 but data only in 2024.

**Recommendation:** Show notice "Only 1 year of data available" when `chartData.length < 2`. Auto-adjust year range.

### D4-7 — HIGH: MyCompany page isolated from rest of workflow

**File:** `src/pages/MyCompanyPage.tsx:60-73, 232`

No other page links to /my-company. KPI labels truncated at `w-32` (128px) with `title` tooltip — inaccessible on touch. No workflow explanation.

**Recommendation:** Add concise workflow explanation. Link from Dashboard empty state.

### D4-8 — MEDIUM: No sample/demo data

No mechanism to show populated state. Every page shows empty state for new users. B2B tool requiring significant setup — users can't evaluate value before investing effort.

**Recommendation:** Add "Load sample data" button in Dashboard EmptyState. Tag with `is_demo: true`. Wipe on first real upload.

### D4-9 — MEDIUM: Calendar automation banner has no prerequisite gate

**File:** `src/pages/CalendarPage.tsx:73-107`

Banner describes full automation pipeline but doesn't check if companies/rules exist. Ingested report will fail silently at document generation step.

**Recommendation:** Show prerequisite warning if companies.length === 0.

### D4-10 — MEDIUM: Loading states inconsistent (6 pages use plain text)

**Files:** `src/pages/TrendsPage.tsx:162`, `src/pages/ReportBuilderPage.tsx:49`, `src/pages/MyCompanyPage.tsx:58`, `src/pages/AnalyticsPage.tsx:148,230,309`, `src/pages/CalendarPage.tsx:146`

Dashboard and Documents use proper skeletons. Six other pages use bare "Loading..." text strings.

**Recommendation:** Extract shared skeleton component. Standardize across all pages.

### D4-11 — MEDIUM: ReportBuilder empty state gives no prerequisite context

**File:** `src/pages/ReportBuilderPage.tsx:51-64, 281`

Report builder requires KPI data to generate anything. Empty KPI checkbox list renders with no message.

**Recommendation:** Guard: if no KPIs, show "Upload and extract reports first."

### D4-12 — LOW: PRIMARY_COMPANY_NAME hardcoded to "Holcim"

**File:** `src/pages/DashboardPage.tsx:168`

`const PRIMARY_COMPANY_NAME = 'Holcim'` — every user sees Holcim as "Primary." The `my_companies` table's `is_primary` flag exists but is not used.

**Recommendation:** Replace with dynamic lookup from `useMyCompanies()`.

### D4-13 — LOW: Scatter plot offers no preset correlation suggestions

**File:** `src/pages/AnalyticsPage.tsx:221-228`

Full KPI list with no categorization, no pre-selection, no example correlations.

**Recommendation:** Add 2-3 "Quick correlation" preset buttons.

## Domain 5: Forms & Input Design

### D5-1 — HIGH: Submit-only validation, no inline field errors

**Files:** All 7 forms

Every form validates only on submit using `toast.error()`. No on-blur or real-time feedback. `aria-invalid` never triggered despite `Input` component supporting it.

**Recommendation:** Add field-level error state. On blur, validate required fields and set `aria-invalid`.

### D5-2 — HIGH: KPI checkbox list — wrong pattern for scale

**Files:** `src/pages/ReportBuilderPage.tsx:280-297`, `src/pages/BenchmarkRulesPage.tsx:221`

128px scroll area (`max-h-32`), no search, no category grouping. BenchmarkRulesPage shows category but ReportBuilder does not.

**Recommendation:** Grouped checkbox list with search input, or tag/pill multi-select. Raise max-h to 256px.

### D5-3 — MEDIUM: Fiscal year input inconsistent type across forms

**Files:** `src/pages/UploadPage.tsx:378` (number input), `src/pages/CalendarPage.tsx:441` (number, no bounds), `src/pages/ReportBuilderPage.tsx:251` (select), `src/pages/MyCompanyPage.tsx:218` (select)

CalendarPage has no min/max bounds. Number input allows spinner to nonsensical values.

**Recommendation:** Standardize on `<select>` with configurable year window.

### D5-4 — HIGH: Company selector — no search on long lists

**Files:** `src/pages/UploadPage.tsx:336-352` (Radix Select), `src/pages/CalendarPage.tsx:412-423` (native select)

Neither supports search/filter. Unusable at scale with dozens of companies.

**Recommendation:** Replace with combobox pattern (searchable select).

### D5-5 — MEDIUM: Notes/Description fields use single-line input instead of textarea

**Files:** `src/pages/CalendarPage.tsx:583-588`, `src/pages/BenchmarkRulesPage.tsx:146-155`

Placeholder suggests multi-sentence content. Single-line input truncates.

**Recommendation:** Replace with `<textarea rows={2}>`.

### D5-6 — MEDIUM: Design system `<Button>` not used in any form

**Files:** All dialog forms

`src/components/ui/button.tsx` has 6 variants. Zero pages use it. All forms use hand-rolled `<button>` with duplicated class strings. Border-radius inconsistency: `rounded-lg` in dialogs, `rounded-full` elsewhere.

**Recommendation:** Replace all form buttons with `<Button>` variants.

### D5-7 — LOW: PasswordGate — no visible label, no loading state

**File:** `src/components/auth/PasswordGate.tsx:53, 65-70`

Label is `sr-only`. Button has no disabled/loading state during async hash check.

**Recommendation:** Add visible label and disabled+spinner during hash.

### D5-8 — MEDIUM: LoginPage password not cleared on tab switch

**File:** `src/pages/auth/LoginPage.tsx:68-72`

Password field retains value when switching between Password/Email Code tabs. Dual email fields across tabs confuse autofill.

**Recommendation:** Lift shared email field above tab switcher.

### D5-9 — MEDIUM: ReviewPage approve has no undo

**File:** `src/pages/ReviewPage.tsx:104-107`

Approving removes row immediately (optimistic update). No confirmation, no undo, no way to re-queue.

**Recommendation:** Add 5-second undo toast using Sonner's action API.

### D5-10 — LOW: Fiscal year default CalendarPage vs other forms (intentional)

CalendarPage defaults to current year (scheduling). Others default to current-1 (reporting). Correct but undocumented.

### D5-11 — MEDIUM: KPI Editor — label truncation loses information

**File:** `src/pages/MyCompanyPage.tsx:232`

Labels capped at `w-32` (128px) with `truncate`. KPI names like "Return on Invested Capital" cut off. `title` tooltip inaccessible on touch/mobile.

**Recommendation:** Full-width stacked layout or `w-40` with wrapping. Add `aria-label` to inputs.

### D5-12 — HIGH: `htmlFor`/`id` pairing missing on most form labels

**Files:** `src/pages/MyCompanyPage.tsx:304`, `src/pages/CalendarPage.tsx:411`, `src/pages/ReportBuilderPage.tsx:214`, `src/pages/BenchmarkRulesPage.tsx:134`

Auth pages correctly use `htmlFor`/`id`. All other forms do not. Clicking label does not focus input.

**Recommendation:** Add `htmlFor` + `id` to every label/input pair.

### D5-13 — MEDIUM: `confirm()` for destructive deletes (cross-ref D2-1)

Same finding as D2-1. `window.confirm()` blocks thread, unstyled, untestable.

### D5-14 — LOW: Description inputs have no maxLength or character counter

## Domain 7: Accessibility & Responsive

### D7-1 — CRITICAL: PasswordGate uses sessionStorage — resets on mobile resize/reload

**File:** `src/components/auth/PasswordGate.tsx:18, 28`

`sessionStorage` is scoped to browser tab. On iOS Safari, viewport resize/rotation can trigger full page reload, clearing session. DevTools resize also clears it.

**Recommendation:** Change to `localStorage` (both read at line 18 and write at line 28).

### D7-2 — LOW: Mobile nav drawer — no focus trap

**File:** `src/components/layout/AppLayout.tsx:167-210`

Structure is correct (hamburger has aria-label, aria-expanded, 44px touch target, Escape closes). But no focus trap when open — keyboard user can tab past drawer into page content.

**Recommendation:** Add useEffect to trap focus when `mobileNavOpen` is true.

### D7-3 — HIGH: Calendar event rows don't stack on mobile

**File:** `src/pages/CalendarPage.tsx:179-263`

Event rows use `flex items-center gap-4` with fixed widths. Action button cluster (4 icons x 32px = 128px) alongside other content in single flex row. No `flex-wrap` or responsive stacking.

**Recommendation:** Restructure to `flex-col` on mobile. Move action buttons to second row.

### D7-4 — MEDIUM: Report action buttons 36px — below 44px minimum

**File:** `src/pages/ReportBuilderPage.tsx:121, 134, 147`

View, Generate, Delete buttons all `min-h-[36px]`. Below 44px WCAG touch target.

**Recommendation:** Increase to `min-h-[44px] min-w-[44px]` or add transparent hit-area padding.

### D7-5 — MEDIUM: AnalyticsPage view tabs — no role="tablist/tab", no aria-selected

**File:** `src/pages/AnalyticsPage.tsx:56-59, 125-138`

Tab buttons are plain `<button>` elements. Not announced as tabs to screen readers.

**Recommendation:** Add `role="tablist"`, `role="tab"`, `aria-selected={active}`.

### D7-6 — MEDIUM: Icon-only buttons missing aria-label

**Files:** `src/pages/CalendarPage.tsx:213-260`, `src/pages/ReportBuilderPage.tsx:139-150`

Use `title` attributes but no `aria-label`. Title not reliably announced on touch devices.

**Recommendation:** Add `aria-label` to all icon-only buttons.

### D7-7 — MEDIUM: Signal red (#EF4444) and amber (#F59E0B) fail WCAG AA on dark cards

**File:** `src/index.css:103-105`

Signal red on card: ~3.8:1 (needs 4.5:1). Signal amber on card: ~3.5:1.

**Recommendation:** Darken signal-red to `#DC2626` (~4.9:1) and signal-amber to `#D97706` (~4.6:1) in dark theme.

### D7-8 — MEDIUM: Color used alone for "worst in peer group" — no secondary indicator

**File:** `src/pages/DashboardPage.tsx:41-48`

Red color conveys "worst" status without a non-color indicator for colorblind users.

**Recommendation:** Add arrow icon or character alongside red values.

### D7-9 — LOW: Loading/skeleton states have no role="status"

**Files:** Multiple pages

Screen readers get no announcement that content is loading.

**Recommendation:** Add `role="status" aria-label="Loading data"` to loading containers.

### D7-10 — LOW: `html class="dark"` hardcoded — ignores OS prefers-color-scheme

**File:** `index.html:2`

App launches in dark mode regardless of user's OS preference.

**Recommendation:** Remove hardcoded class. Configure theme provider with `defaultTheme="system"`.

### D7-11 — LOW: Mobile nav drawer — no scroll lock

**File:** `src/components/layout/AppLayout.tsx:167-210`

Body scrolling not locked when drawer is open.

### D7-12 — LOW: Sticky company column uses bg-inherit — may bleed on mobile scroll

**File:** `src/pages/DashboardPage.tsx:356`

`bg-inherit` may not correctly inherit row backgrounds set with Tailwind opacity modifiers.
